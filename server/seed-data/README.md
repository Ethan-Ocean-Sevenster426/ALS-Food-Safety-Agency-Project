# Seed snapshot

This folder holds a human-readable snapshot of the development database so other developers can see exactly what the seed scripts produce.

## `snapshot.xlsx`

One workbook, one sheet per table. Generated by
[`server/scripts/exportSeedSnapshot.js`](../scripts/exportSeedSnapshot.js).

Tables included:

| Sheet | Row count at last export |
| ----- | ------------------------ |
| Users | 21 (1 Super Admin, 3 Admins, 15 Inspectors, seeded Company Admins + Users)* |
| ConsolidatedMasterAbattoirDatabase | 14 facilities (one per inspector) |
| EggProductionVerifications | 378 (210 facility + 168 inspector) |
| Invitations, EPVAuditLog, EPVAttachments, EPVInvoices, ClientAuditLog | audit / relational data |
| LoginLog | login attempt history |
| KPITargets | dashboard KPI thresholds |
| SupportTicketCategories, SupportTickets, SupportTicketComments | support workflow |
| EmailSendLog | outbound email audit |

*`PasswordHash` is redacted in every row — never commit raw bcrypt hashes.

## Refreshing the snapshot

```bash
cd server
node scripts/exportSeedSnapshot.js
```

## Restoring the snapshot into your DB

After initialising a fresh database (`npm run init-db` + every migration
under `server/scripts/`), replay the snapshot:

```bash
cd server
node scripts/importSeedSnapshot.js
```

This wipes every table contained in the snapshot and re-inserts every
row with IDs preserved. Password hashes are regenerated on the fly
(snapshot scrubs them):

| User | Password |
|------|----------|
| `anthony@epvs.com` | `StrongPassword123!` |
| every other seeded account | `Password@123` |

The snapshot is the **only** seed data shipped with the repo - the
earlier hard-coded `seed-*.js` scripts have been removed.
